# P2 扩展功能 (`:extend`) 实施规划

根据代码库现状分析，`:extend` 功能目前在 AST 中有定义结构但未集成，解析器和编译器均未支持。这是一个复杂的特性，建议分为两个阶段实施。

## 📅 阶段规划

### 🛠️ 第一阶段：AST 与解析器支持 (当前任务)
**目标**：让编译器能够识别和解析 `:extend` 语法，建立数据结构基础，虽然暂时不产生 CSS 效果，但能通过语法检查。

1.  **升级 AST (`src/ast/mod.rs`)**
    *   将 `Extend` 结构体集成到 `Statement` 枚举中：`Statement::Extend(Extend)`。
    *   确保 `Extend` 结构体包含所需的所有信息（选择器列表、`all` 关键字等）。

2.  **升级解析器 (`src/parser.rs`)**
    *   实现 `parse_extend` 方法：专门解析 `&:extend(selector);` 形式的语句。
    *   增强 `parse_statement`：识别 `&` 开头的语句，区分是普通嵌套规则还是扩展指令（根据结尾是 `{` 还是 `;` 判断）。
    *   *注*：附加在选择器上的扩展（如 `.a:extend(.b) {}`）将作为选择器的一部分解析，可能需要后续增强 `Selector` 解析逻辑。

3.  **验证测试**
    *   创建 `tests/test_extend_parsing.rs`。
    *   测试用例：
        ```less
        .a {
            &:extend(.b);      // 简单扩展
            &:extend(.c all);  // 带 all 关键字
        }
        ```
    *   验证解析器是否正确生成了 `Statement::Extend` 节点。

### ⚙️ 第二阶段：编译器逻辑实现 (后续任务)
**目标**：实现选择器合并逻辑，生成正确的 CSS。

1.  **预处理/收集**：在编译 CSS 规则前，需要先收集当前作用域下的所有 `extend` 指令。
2.  **选择器匹配**：实现复杂的选择器匹配算法，找到被扩展的目标规则。
3.  **规则重写**：将当前选择器追加到目标规则的选择器列表中（例如 `.b, .a { ... }`）。
4.  **处理 `all` 关键字**：支持深度匹配和嵌套结构扩展。
